# pool-factory TypeScript binding

Typed Soroban RPC client for the Spreadless pool factory.

## Authority model

The factory owner is Spreadless protocol governance. Ownership uses
OpenZeppelin Stellar's two-step transfer flow and may be transferred to a
multisig contract address. Renunciation is disabled.

Every pool created by this factory permanently records the factory contract
address as its protocol controller. Transferring factory ownership therefore
transfers protocol control over all registered pools without rewriting each
pool.

## Factory defaults

The constructor requires:

```ts
{
  owner: string;
  pool_wasm_hash: Buffer;
  default_protocol_fee: bigint;
  default_protocol_beneficiary: string;
}
```

The protocol fee uses `1_000_000_000n == 100%` and represents the protocol's
share of each pool's swap fee.

Defaults are copied into a pool when it is created. Updating a default affects
future pools only and never changes an existing pool.

## Pool creation

```ts
const tx = await factory.create_pool({
  creator,
  tokens,
  amp_factor: 100,
  amp_control: { tag: "ProtocolManaged", values: undefined },
  swap_fee: 100_000n,
  max_caps,
  lp_max_supply,
  lp_name: "Spreadless LP",
  lp_symbol: "SLP",
});
```

Creation is permissionless, but `creator` must authorize the transaction. The
creator becomes pool owner. The creator cannot choose the protocol fee or
beneficiary.

The irreversible amplification modes are:

- `Locked`: the initial amplification factor can never change.
- `ProtocolManaged`: factory governance may apply an immediate change or
  start a linear ramp.

## Governance methods

Factory defaults and future pool code:

- `set_pool_wasm_hash({ new_hash })`
- `set_default_protocol_fee({ new_fee })`
- `set_default_protocol_beneficiary({ new_beneficiary })`

Registered-pool proxies:

- `set_pool_protocol_fee({ pool_id, new_fee })`
- `set_pool_beneficiary({ pool_id, new_beneficiary })`
- `set_pool_amp_ramp({ pool_id, target_factor, duration })`
- `pause_pool({ pool_id })`
- `unpause_pool({ pool_id })`

All require factory-owner authorization. Pool proxies reject targets outside
the factory registry. Pool-specific settings are independent of factory
defaults.

## Registry

On-chain registry methods:

- `next_pool_id()` returns the ID that will be assigned next.
- `pool_at({ id })` resolves a pool and refreshes that entry's TTL.

Use `PoolCreated` events for off-chain discovery. Read the
`AssembledTransaction.result` field for generated view methods.

## Building

```sh
npm ci
npm run build
```

The contract-derived portion of `src/index.ts` is regenerated by the
repository's `make bindings` target.
